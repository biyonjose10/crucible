## The one idea everything serves

**The sandbox computes the grade; the model only explains it.**

`lib/scoring.ts` is a pure function from test results to a score report. It
imports **only** `lib/types.ts` and has no path to any language model.
`npm run verify` fails the build if that import list ever changes. This is the
whole pitch — do not add a model call, a heuristic, or a "confidence adjustment"
anywhere in the grading path.

The model is shown *only* failing-test evidence and cannot express a score:
there is no `score`/`grade`/`points`/`earned`/`mark` field anywhere in the
diagnosis types or the API response, deliberately.

## Stack and the non-obvious decisions

Next.js 16 · React 19 · Tailwind 4 · TypeScript · motion · Google Gemini.

- **Python runs client-side in Pyodide (CPython 3.14 in WASM)**, self-hosted
  from `public/pyodide`. That directory is gitignored and regenerated at build
  time by `scripts/copy-pyodide.mjs` (wired to `predev`/`prebuild`).
- **Piston is dead — do not go back to it.** The original plan used the Piston
  public API; it went whitelist-only in Feb 2026 and returns 401. Pyodide is
  better anyway: no key, no rate limit, no third-party outage mid-demo, and
  `Worker.terminate()` genuinely kills an infinite loop.
- The 5s execution budget starts **after** the interpreter is warm, so a ~4s
  cold start is never charged against a student's submission.
- Clause scoring is all-or-nothing. A test that never reported is
  `inconclusive` — never assumed to pass, never assumed to fail.
- Diagnosis fires **lazily per expanded card**, so a 30-student run costs $0
  until someone opens one. A clean pass never calls a model at all.

## Hard-won lessons — do not regress these

1. **Never gate visibility on a frame-driven animation.** Entry animations run
   on rAF, which browsers throttle in backgrounded tabs. Animating `opacity`
   from 0 meant a link opened in a background tab showed a blank page; measured
   25 of 30 cards stuck at opacity 0 on the deployed build. Same class of bug:
   `AnimatePresence mode="wait"` once held the queue's mount behind the hero's
   exit animation, so a finished 30/30 run still displayed the landing page.
2. **The Vercel CLI rewrites `.env.local`.** `vercel link` overwrote it with an
   OIDC token; a later command commented the key line out with `#`. **Do not run
   `vercel link` or `vercel env pull` in this project.**
3. **`AGENTS.md` is regenerated by `next dev`** — don't fight it.

## Credentials

`GEMINI_API_KEY` lives in `.env.local` (gitignored) and in Vercel's env store.
It is the **shared `...HMPA` key also used by FairLens and KSP Copilot**, it has
already leaked once, and it **cannot be easily rotated** (Google requires new
keys to be service-account-bound and that project has none). Deleting it breaks
three projects. The user chose this reuse knowingly.

Because the repo is public:
- `.githooks/pre-commit` refuses any staged env file or credential-shaped
  string. Enable on a fresh clone with `npm run setup-hooks`.
- `npm run scan-secrets` sweeps working tree **and full git history**. Run it
  before any push.
- Note: `GEMINI_API_KEY` is *also* set as a Windows User-scope env var, which
  can mask a missing `.env.local` during testing.

## Known, accepted risk — no rate limiting

`/api/diagnose` is public, accepts arbitrary code, and calls Gemini on every
request with no per-visitor limit, no body-size cap and no daily spend ceiling.
Each call costs roughly $0.003 on a **real billing account**, using the shared
`...HMPA` key that cannot be quickly rotated. A scripted caller could run up a
material bill, and the only remedy would be deleting a key three projects
depend on.

This was raised on 2026-08-27 and the user chose not to fix it before the
deadline. Do not silently re-litigate it — but if abuse actually appears, the
fix is a per-IP limit plus a daily spend ceiling that degrades to the existing
`unavailable: true` path, which is already built and tested.

## Fixtures — these numbers are load-bearing

`fixtures/archetypes.ts` defines 8 submissions driving a seeded 30-student class
(`fixtures/class.ts`). `scripts/verify.ts` asserts each score exactly:

| Archetype | Score | Why it exists |
|---|---|---|
| correct | 10/10 | no false negatives |
| off-by-one | 8/10 | the pedagogy beat |
| int-return | 8/10 | rubric granularity |
| infinite-loop | INCONCLUSIVE | Worker.terminate() at 5s |
| syntax-error | 0/10 | diagnosis works with no execution |
| **prompt-injection** | **4/10** | tells the grader to award full marks; scored by tests anyway |
| hardcoded | 4/10 | passes 5/5 visible, fails 5/7 hidden |
| empty-crash | 8/10 | the empty-list contract |

Note: two hidden tests legitimately **pass** for `hardcoded` (`median(list())`
still raises, `0.0` is still a float). The assertion is "all visible pass and
≥5 of 7 hidden fail" — don't tighten it to "all hidden fail", that's false.
